Test Sistemi

Test Nedir?

Test, yazılımda işlevlerin doğru çalışıp çalışmadığını doğrulamak için kullanılan bir terimdir. Normalde testler yazılımcılar tarafından yapılsada bazen unutulan bir yöntem veya bir bilgi eksik girilir ve sanki işlev doğru gözükür. İşte bu gibi durumlarda test kütüphaneleri kullanılır.

Unit Test Nedir?

Unit test, yazılım geliştirme sürecinde her bir birimin tek tek test edilmesi ve sonuçlarının değerlendirilmesine denir. Her bir birim bağımsız çalışırve test edilir. Böylelikle daha verimli ve kaliteli kodlar yazılabilir.

CUnit

CUnit, C porgramlama dilinde Unit test kütüphanesidir.
Kurmak için;
Windows;

pacman -Sy mingw-w64-86_64-cunit

Linux;

sudo apt install libcunit1 libcunit1-doc libcunit1-dev
Öğrenmek için ufak bir kod yazalım. Kodumuz, bir dosyayı yazma üzerine olsun. Dosyanın içerine "Hello CUnit" yazdıralım ve program çıktısını gözlemleyelim.
#include <stdio.h>

#include <CUnit/CUnit.h> // CUnit genel kütüphanesi
#include <CUnit/Basic.h> // CUnit'in basit arayüzü için kütüphane
 
FILE* testDosya = NULL;
// Genel test dosyamız

static int initTest() // CUnit testlerinde bir başlangıç fonksiyonu vardır. Test bu fonksiyonda başlar ana fonksiyondan devam edilir
{
    testDosya = fopen("testFile", "w");// Dosyayı yazma modunya açmaya çalışıyoruz

    if (testDosya != NULL) // Eğer başarısız olmazdayısa
        return CUE_SUCCESS; // CUnit'in "başarılı" makrosunu gönder
    else // Değilse
        return CUE_FOPEN_FAILED; // CUnit'in "Fopen başarısız oldu" makrosunu gönder
}

void test(void) // Ana test fonksiyonumuz. Bu fonksiyon başlangıç fonksiyonundan sonra çalıştırılır
{
    CU_ASSERT(fprintf(testDosya, "Hello CUnit") == 11);
    // Assert ile test ediyoruz
    // fprintf(testDosya, "Hello CUnit") == 11; İçerisi CUnit'in iddia edilecek işlemlerdir. Bu kısımda fprintf'ın başarılı olup olmadığına dair bir iddia bulunduk
}

static int cleanTest() // CUnit testlerinde bir de son fonksiyon vardır. Bu fonksiyonda, ana test fonksiyonu bittiği an çalıştırılan ve genelde başlangıç ve ana fonksiyonların artıklarını temizler
{
    fclose(testDosya);

    if (testDosya != NULL) // Eğer başarılı bir şekilde kapatıldı ise
        return CUE_SUCCESS;
    else // Değilse
        return CUE_FCLOSE_FAILED;  // CUnit'in "Fclose başarısız oldu" makrasonu gönder
    
}

int main()
{
    CU_initialize_registry(); // Genel CUnit'ın genel kayıtçısını başlat

    CU_pSuite birinciBolme = CU_add_suite("Bolme1", initTest, cleanTest);
    // Test bölmesi oluşturmamızı sağlar. Test bölmeleri testlerin barındığı ve sınıflarndırıldığı kısım gibidir
    // "Bolme1"; Bölmenin adı
    // initTest; Başlangıç fonksiyonu
    // cleanTest; Temizleme fonksiyonu

    CU_pTest birinciTest = CU_add_test(birinciBolme, "test1", test);
    // Bölmeye test eklememizi sağlar
    // birinciBolme; Eklenecek bölmenin yapısı
    // "test1"; Eklenecek testin ismi
    // test; Eklenecek test fonksiyonu

    CU_basic_set_mode(CU_BRM_VERBOSE); // CUnit arayüzlerinde olan BASIC'e ayar ekler. Bu kısımda bize her şeyi göster diyoruz
    CU_basic_run_test(birinciBolme, birinciTest);
    // Testi başlatmamızı sağlar
    // birinciBolme; Testin bölmesi
    // birinciTest; Test yapısı

    CU_cleanup_registry(); // Genel kayıtçıyı temizler

    return 0;
}

 -lcunit ile derleyerek çalıştırdığımızda çıktımız;

Test Yazma Prensibleri

Test yazarken bazı prensibler vardır. AAA olarak bilinen ve açılımı Arrange-Act-Assert(Hazırlık-Eylem-İddia) test yazma prensibidir. Her bir A'nın anlamı vardır. İlk olarak teker teker açıklayalım.

Arrange(Hazırlık)

Test yapmadan önce değişkenlerin ve fonksiyonların tanımlandığı ve test edilecek kısımların test bölümlerine ve test yapılarına katılmasıdır. CUnit örneğinde verdiğimiz kodda o kodu yazarken aslında biz Arrange aşamasında oluruz.

Act(Eylem)

Arrange aşamasında yazılan kodları çalıştırma aşamasıdır. Örneğimizde bu durum kodları derleyip çalıştırmamızla eş değerdir.

Assert(İddia)

Assert ise Act'an gelen çıktıyı inceleyerek, CUnit'in bizlere ne kadar iddia bulunduğunu yani "Şu kısımda hata çıkabilir" dediği kısımlara denir. Eğer kaliteli ve hatasız kod yazmak istiyorsak mümkün olduğunca CUnit'in en az iddiada bulunduğu kodlar yazmaktır. Bu kısım kodda "CU_ASSERT(fprintf(testDosya, "Hello CUnit") == 11);"
         olarak ifade edilir.
Kodun çıktısında gelen tabloda birler hataları temsil ederken, sıfırlar hatasız olanları temsil eder.
