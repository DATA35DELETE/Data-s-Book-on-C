Bellek Yönetimi

Bellek Yönetim Nedir?

Bellek yönetimi, bir programda hangi işlemde ne kadar bellek yönetilmesini belirleyen yönetimlerine bellek yönetimi denir.
Java veya Python gibi dillerde bellek yönetimi konusu pek karşınıza çıkmayabilir. Çünkü bu işi genelde dilin kendisi halletmektedir. Peki ya C'de? C için durumlar tam tersidir. Bahsetiğimiz gibi C programlama dilinde her işlem "manual" olarak yazılmalı ve çalıştırılmalıdır. Bunun da pek tabi sebebi C progrmalama dilinin, tüm dillerin atası olmasıdır. Eğer Python dilinin Github sayfasına baktı iseniz, "Diller" bölümünde %35.8 gibi bir oran ile C yazılım dilini içerdiğini görüceksiniz.
Peki C programlama dilinde bellek yönetimi nasıl? Neredeyse tamamiyle "manual" yani yazılımcının bu işi yapması gerektiğini görürüz. İş bu yüzden C programlama dilinde bellek yönetimi konusu öpk ama çok önemlidir.
Bellek yönetimi kavramında iki tür bellek alanı üzerinden çalışılır. Bunlardan biri Stack diğeri ise Heap'tir. Gelin bu iki kavramı anlatmaya çalışalım...

Stack

Stack; bellekte program başlatıldığında, sabit boyutlu değerlerin depolanbilceği bir bellek alanıdır.
Stack, LIFO yani [Last in, First Out(Son Giren, İlk Çıkar)] prensibi ile çalışır. Bu prensibi aslında bir nevi elma sepete benzetebiliriz. Mesela, 5 tane elmamız olsun ve bu elmaları sepetimize koymuş olalım. Gösterimsel ve yazımsal olarak gösterirsek ise şu şekil gözükücektir.
Elmalarımızı(elma1, elma2, elma3, elma4, elma5) sırayla sepetimize eklemiş olalım. Daha sonra sepetimizi boşaltmak istediğimiz zaman ilk çıkacak elma, en son giren koyulmuş olan elma5 olucaktır. İşte bu sisteme LIFO sistemi denir.
İşte Stack bellek alanında veriler bu şekilde saklanırlar. Amacı ise fonksiyon ve yapı çağrılarını depolamak ve hızlı bir şekilde işlemektir.

Heap

Heap, bellekde dinamik yani daha sonradan boyutu değişebilen veriler için bir bellek alanıdır.
Heap, Stack'in aksine yavaştır ve uzun ömürlü ve dinamik veri yapıları için kullanılır.
Heap ise FIFO[First in, First out(İlk Giren, İlk Çıkar)] prensibi ile çalışır. Bu prensibi ise bir banka kuyruğuna benzetebiliriz. Kuyruğa kim ilk girdiyse, haliyle ilk işi bitende o olucağıdan kuyruktan ayrılanda ilk giren olur.

Bellek Katmanları

Bellek katmanları, RAM donanımının içerisinde geçici depolanan verilerin nasıl depolandığını göre katmanlar kullanılır. Bellek dört bölmeden oluşmaktadır; Yazı katmanı, veri katmanı, Heap katmanı ve Stack katmanlarından oluşur.
Her bir katmanın kendine has görevleri ve veri depolama şekilleri vardır. Şimdi sırayla inceleyelim.

Yazı Katmanı(Text Segment)

Yazı katmanı, belleğin en alt katmanıdır. Bu katmanda, yazılan kodların derlenmiş içerikleri bulunur.
Bu katmanda program akışı içerisinde herhangi bir oynama sonucu programı bozma ihtimali bulunduğudan, salt okunur yani sadece okunabilir yazılamaz formatında saklanır. Böylelikle programın içeriği korunmuş olur.
Burdan şunu anlıyoruz ki yazdığımız programlar HDD veya SSD'lerde değil RAM'de çalıştırılır. Program kapatıldığında otomatik bir şekilde katmandan, kapatılan programın içeriği silinir.

Veri Katmanı

Bu katman ise değişkenlerin ve yapıların depolandığı kısımdır.
Veri katmanı iki bölümden oluşur. Başlatılmış ve başlatılmamış diğer bir adıyla BSS.
Başlatılmış bölümünde, program içerisinde programcı tarafından veri atanan değişkenler saklanır.
BSS ise program içerinde programcı tarafından veri atanmamış değişkenler saklanır. C programlama dilinde bu bölümde saklanan değişkenlere otomatik şekilde sıfır değerini atamaktadır.
Şimdi ise programda iki adet değişken tanımlayalım. Bir tanesini başlatılmış diğerini ise BSS şeklinde oluşturalım.
int main() {
    int BSS_Degisken; // Bu değişken veri segmenti katmanındaki BSS bölümünde saklanır
    
    int baslatilmisDegisken = 42; // Bu değişken veri segmenti katmanındaki başlatılmış bölümünde saklanır

    return 0;
}

Heap Katmanı

Heap, yukarıda anlattığımız veriler için bir veri katmanıdır.
C tarafında bu kısım Pointer'ların saklandığı ve göreceğimiz olan malloc ve calloc fonksiyonların bellek ayırdığı kısım bu kısımdır.
int *ornekPtr;

Stack Katmanı

Stack'de yukarıda anlattığmız gibidir.
C tarafında bakacak olursak, verisi ve boyutu belli olan verilerin saklandığı kısımdır.
int ornekStack = 42;

Segment Hataları

Segment hataları, bir programın kendi alandan dışına çıkıp, ona ait olmayan bir bellek alanındaki verilere değiştirldiğinde ortaya çıkan bir hatadır.
Segment hataları, genelde gerçekleştiğinde programın çökmesiyle sonuçlanan bir hatadır.
Segment hatası diğer adıyla Segfault'un nedenleri listle şeklinde verilmiştir;
  • Geçersiz(NULL) olan Pointer'lara erişim.
  • Dizi boyutunu aşan işlemleri gerçekleştirme.
  • Bellek sızıntıları ve serbest bırakılmamış dinamik veriler.
Bunlar Segfault'a neden olabilcek programlama hatalarıdır. Şimdi bir NULL değerine sahip Pointer tanımlayalım ve erişmeye çalışalım.
#include <stdio.h>

int main() {
    int *ptr = NULL;
    *ptr = 12; // Segfault çıkacağı kısım

    return 0;
}

Çıktımız "Segmentation fault" olucaktır.

Malloc

Malloc, C programlama dilinde RAM'de dinamik bellek ayırmak için kullanılan bir fonksiyondur. Malloc, "stdlib.h" kütüphanesinde yer alır. Bu sebele kod dosyamıza "stdlib.h" kütüphanesini eklemeliyiz.
tür *isim = (tür *)malloc(baytCinsindenAyrilacakAlan);
        
Şeklinde bellekten yer ayırtırız.
Malloc, bellekte alan ayrırken nasıl bir veri ile ayırdığını kontrol etmez. Bu yüzden genelde belleğin programcı tarafından veri atanmamış kısımları çöp verilerle doludur.
Evet... Teorik konuştuğumuz yeter, şimdi pratik olarak ele alalım.
#include <stdio.h>
#include <stdlib.h> // Kütüphanemiz


int main(){

    int *sayilar = (int *)malloc(5 * sizeof(int)); // Bu kısımda sizeof kullandık çünkü, sizeof(int)'in değeri burada 4'tür. Biz bunu 5 ile çarptık ve 20 sonucu elde ettik. C'de 20 baytlık bir alan ayırdı. Bu kısımda sizeof kullanmamızın sebebi okunabilirliktir. Çünkü eğer yanlış hesaplarsak program çökücektir. Çünkü biz her ne kadar 20 baytlık bir alan ayırmış olsakda aslında bizi ilgilendiren kısım "bu bellekte kaç tane Integer depolanır?" olucaktır. 20 baytlık bir alanda 5 tane Integer yer alır. Oda yıldız işaretinin sol kısmındadır. Bu sebeble bu format kullanılır

    *(sayilar) = 12; // Bellek ayırdığımız yapıyı bir nevi diziye benzetebiliriz. Şuan yaptığımız bir nevi bir dizinin sıfırıncı Index'deki elemana erişmektir. Diğer Index'deki değerere erişmek için *(sayilar + i) kullanılır. i, Index'i temsil eder

    printf("Ozel ayrilan bellek alaninda 0. Index'deki deger: %d\n", *(sayilar)); // Çıktı 12 olucaktır
    printf("Ozel ayrilan bellek alaninda 1. Index'deki deger: %d\n", *(sayilar + 1)); // Program tarafından atamamış olsakta eriştiğimiz zaman rastgele bir değer getirir. Bunun sebebi ise bahsettiğimiz gibi malloc bellekte yer ayırırken, nasıl ayırdığını bakmaz. Her çalıştırmada değişmektedir

    return 0;
}

Calloc

Calloc; Malloc'tan farklı olarak bellekte yer ayırırken, ayırdığı kısımdaki verileri temizler değerlerini sıfıra atar. Bu özelliği sayesinde Malloc yerine tercih edilir.
tür *isim = (tür *)malloc(baytCinsindenAyrilacakAlan, sizeof(tür));
        
Şeklinde ayrıltırılır.
Şimdi size verdiğimiz örneği Calloc ile yeniden yazalım ve farkı görelim.
#include <stdio.h>
#include <stdlib.h>

int main(){

    int *sayilar = (int *)calloc(5, sizeof(int));

    *(sayilar) = 12;

    printf("Ozel ayrilan bellek alaninda 0. Index'deki deger: %d\n", *(sayilar)); // Çıktı 12 olucaktır
    printf("Ozel ayrilan bellek alaninda 1. Index'deki deger: %d\n", *(sayilar + 1)); // Çıktı 0 olucaktır

    return 0;
}

Hata Kontrolü

Her şeyin kesin olmadığı gibi Malloc ve Calloc ile ayırdıkları da kesin değildir. Eğer bir RAM dolu ilse ayırma işlemi başarız olursa metodlar NULL döner ve biz bunu kontrol etmeliyiz. Yoksa program "Segmentation fault" hatalarıyla dolar.
Şimdi ki örneğimizi NULL kontrollü şekilde yeniden yazalım.
#include <stdio.h>
#include <stdlib.h>

int main(){

    int *sayilar = (int *)calloc(5, sizeof(int));
    if (sayilar == NULL)
    {
        printf("Bellek ayrilamadi"); // Bildirme

        return 1; // Programın hata ile sonuçlandığını bildirmek için 1 ile dönüyoruz
    }
    

    *(sayilar) = 12;

    printf("Ozel ayrilan bellek alaninda 0. Index'deki deger: %d\n", *(sayilar)); // Çıktı 12 olucaktır
    printf("Ozel ayrilan bellek alaninda 1. Index'deki deger: %d\n", *(sayilar + 1)); // Çıktı 0 olucaktır

    return 0;
}

Çıktı büyük ihtimalle değişmicektir. Fakat eğer bellek beş bayttan bile az bir alan kaldı ise Calloc bu kısımda NULL döner.

Realloc

Realloc ise Malloc veya Calloc ayırdığımız belleklerin boyutlarını büyütmemiz için kullandığımız fonksiyondur. Eğer başarısız olursa NULL döner.
isim = (tür *)realloc(isim, yeniBoyutu);
        
Şeklinde yeniden boyutlandırılır.
Şimdi ise verdiğimiz örnekte Realloc kullanalım ve "sayilar" bellek alanımızı beş adet Integer alanından(yirmi Bayt) on tane Integer alabilecek(kırk Bayt) bir bellek alanına dönüştürelim. Ardından sekizinci Index'deki elemana bir değer atıyalım ve yazdıralım.
#include <stdio.h>
#include <stdlib.h>

int main(){

    int *sayilar = (int *)calloc(5, sizeof(int));
    if (sayilar == NULL)
    {
        printf("Bellek ayrilamadi"); // Bildirme

        return 1; // Programın hata ile sonuçlandığını bildirmek için 1 ile dönüyoruz
    }
    

    *(sayilar) = 12;

    printf("Ozel ayrilan bellek alaninda 0. Index'deki deger: %d\n", *(sayilar)); // Çıktı 12 olucaktır
    printf("Ozel ayrilan bellek alaninda 1. Index'deki deger: %d\n", *(sayilar + 1)); // Çıktı 0 olucaktır

    // *(sayilar + 8) = 34; | Normal şartlarda boyutu yermeze bile bu tarz bir erişim sağlayabiliriz. Lakin bu işlem aslında bize ait olmayan bir bellek alanında işlem anlamına gelir. Bu durum, eğer işlem gerçekleştirdiğimiz bellek alanının gerçek sahibi gelip oaraya kendi verisini yazmadığı sürece sorun çıkarmaz. Ama yazarsa bizim programımız çökücektir. Aynı durum karşı program içinde geçerlidir

    sayilar = (int *)realloc(sayilar, 10 * sizeof(int)); // 20 bayt -> 40 bayt
    if (sayilar == NULL)
    {
        printf("Bellek ayrilamadi"); // Bildirme

        return 1; // Programın hata ile sonuçlandığını bildirmek için 1 ile dönüyoruz
    }

    *(sayilar + 8) = 34; // Şimdi güvenli bir şekilde işlem yapabiliriz. Çıktı 34 olmalıdır

    printf("Ozel ayrilan bellek alaninda 8. Index'deki deger: %d\n", *(sayilar + 8));

    return 0;
}

Free

Free, Malloc veya Calloc ile ayrıldığımız bellek alanlarını serbest bırakır.
free(isim);

Şeklinde serbest bırakılır.
Free çok önemlidir. Özellikle program akışı içersinde işimizin bittiği bellek alanlarını serbest bırakmak yani boşaltmak çok ama çok önemlidir. Bunun sebebi ise gereksiz yere tutulmuş bellek alanları bizlere hem veri sızıtısına hem de luzümsüz bir bellek tüketimine yol açar. Eğer belleği fazla şişirirsek program bir yerden sonra çöker. İşte bu yüzden hem program kapatılmadan önce hem de program akışı içersinde işimizin bittiği bellek alanlarını serbest bırakmalıyız ki RAM'i verimli kullanalım.
Artık son dokunuş olarak Free ile de bellek sızıntılarını önleyelim.
#include <stdio.h>
#include <stdlib.h>

int main(){

    int *sayilar = (int *)calloc(5, sizeof(int));
    if (sayilar == NULL)
    {
        printf("Bellek ayrilamadi");

        return 1;
    }
    

    *(sayilar) = 12;

    printf("Ozel ayrilan bellek alaninda 0. Index'deki deger: %d\n", *(sayilar));
    printf("Ozel ayrilan bellek alaninda 1. Index'deki deger: %d\n", *(sayilar + 1));

    // *(sayilar + 8) = 34;

    sayilar = (int *)realloc(sayilar, 10 * sizeof(int));
    if (sayilar == NULL)
    {
        printf("Bellek ayrilamadi");

        return 1;
    }

    *(sayilar + 8) = 34;

    printf("Ozel ayrilan bellek alaninda 8. Index'deki deger: %d\n", *(sayilar + 8));

    free(sayilar); // En sonda "sayilar" bellek alanını serbest bıraktık

    return 0;
}

Böylelikle tertemiz bir programımız oldu.

Bellek Hataları

Tek hatasız olmayan Malloc veya Calloc değildir. Bizlerde hatasız değiliz. İşte bellek alanında programcı tarafından, bellek kısmında yapılan hatalara bellek hataları denir.

Dangling Pointer

Dangling Pointer yani sarkan işaretçi hatası, Free edilmiş bir bellek alanına erişmeye çalışmaya çalışdığında ortaya çıkan hatadır. Dönen veri rastgele olur.
Örneğimizi bu konu üzerine güncelleyelim.
#include <stdio.h>
#include <stdlib.h>

int main(){

    int *sayilar = (int *)calloc(5, sizeof(int));
    if (sayilar == NULL)
    {
        printf("Bellek ayrilamadi");

        return 1;
    }
    

    *(sayilar) = 12;

    printf("Ozel ayrilan bellek alaninda 0. Index'deki deger: %d\n", *(sayilar));
    printf("Ozel ayrilan bellek alaninda 1. Index'deki deger: %d\n", *(sayilar + 1));

    // *(sayilar + 8) = 34;

    sayilar = (int *)realloc(sayilar, 10 * sizeof(int));
    if (sayilar == NULL)
    {
        printf("Bellek ayrilamadi");

        return 1;
    }

    *(sayilar + 8) = 34;

    printf("Ozel ayrilan bellek alaninda 8. Index'deki deger: %d\n", *(sayilar + 8));

    free(sayilar);

    printf("Ozel ayrilan bellek alaninda 8. Index'deki deger: %d\n", *(sayilar + 8)); // Free edilmesine rahmen 8. Index'sine erişmeye çalışalım. Belki aynı değeri 34 yazdırabilir ama şuan bize ait olmayan bir bellekten veri almış olduk

    return 0;
}

Buffer Overflow

Buffer Overflow yani bellek taşması, bir bellek alanına, alanından fazla veri yazdırmaya Buffer Overflow denir.
Bu durum genelde kullanıcıdan girdi alma sırasında meydana gelir. Biz programda yirmi karakterlik bir veri istiyebiliriz. Ama kullanıcı bize kırk karakterlik bir veri girerse, yirmi karakter bellek alanına diğer yirmi karakter ise belleğin hemen yanındaki belki bize ait olmayan bir belleğe yazılır. Bu durum küçük hatalardan devasa sistem açıklarına kadar geniş bir yelpazede risk oluşturmaktadır.
Bellek taşması yaşatıcak bir program yazalım. Scanf ile izah edelim ki en çok hata Scanf'den çıkar. Çünkü Scanf ne uzunlukta veri girildiğine bakmazsızın direkt veriyi değişkene yazar.
#include <stdio.h>

int main(){

    char girdi[20]; // 19 karakterlik bir girdi değişkenimiz

    scanf("%s", &girdi); // İşte tam bu kısımda bellek taşması olayı söz konusudur. Eğer kullanıcı 19 karakter yerine 40 karakter girerse bellek taşıcaktır

    printf("%s", girdi);

    return 0;
}

RAM'de İletişim (Shared Memory)

Shared Memory, bir bilgisayarda iki veya ikiden fazla program için ayrılan özel bellek alanlarına RAM'de iletişim nedir.
Peki RAM'de iletişim bizim için ne katkısı olucak? Tabikide iki programın aralarında özel bir iletişim hattı için hayati önem taşır. Örneğin; İki adet programımın olsun. Birisi kullanıcıdan girdileri alsın, diğeri ise o programın aldığı girdiği RAM'de iletişim sağlayarak gelen veriyi işlesin ve tekrar aynı hattan bir sonuç göndersin. Bu mimari sıkça devlet ve banka hizmetlerindeki bilgisayarlar ve bilgi işlem merkezlerinde kullanılır. İşte bu yüzden RAM'de iletişim, güvenli bir şekilde programlar arasında veri alış-verişini sağlar.

Mmap

Mmap; bellekde özel yer ayrırken, Malloc veya Calloc ile ayrılan belleklerden aksine Kernel yani çekirdek seviyesinde bellek ayırmamızı sağlar. İşlevin sonucu bir Pointer dönmektedir.
türü *mmapKullanimi = mmap(NULL, 5 * sizeof(türü), PROT_READ | PROT_WRITE, MAP_PRIVATE | MAP_ANON, 0, 0);

türü: Mmap'in açacağı bellek alanın hangi tür değişkenden olcağını belirler
NULL: Mmap'in isterksek spesifik bir bellek alanında açılmasını istiyebilmemizi sağlar. NULL girilirse Mmap otomatik ayarlamaktadır.
5 * sizeof(türü): Mmap'in bellekte kaç bayt yer açacağını belirler.
PROT_READ | PROT_WRITE: Mmap'in bellekte açtığı kısımda hangi işlemlere izin verilip verilmeyeceğini belirler. (PROT_READ: Okumayı Kabul Eder. PROT_WRITE: Yazmayı Kabul Eder.)
MAP_PRIVATE | MAP_ANON: Mmap'in görünürlüğü ve erişimliğini belirler. (MAP_PRIVATE: Özel. MAP_SHARED: Paylaşımlı. MAP_ANON: Anonimlik sağlanır.)

şeklinde tanımlanmaktadır.

Ayrıca eğer bellek ayırma işlemi başarısız olursa MAP_FAILED değişlenini döner.

Ayrıca Malloc ve Calloc'da olduğu gibi bu sistemde de Free edilmesi gerekir. Bu konuda Free'nin karşılığı Munmap fonksiyonudur. Eğer bu fonksiyon başarısız olur ise sıfır döner.

munmap(mmapKullanimi, 5 * sizeof(türü));

mmapKullanimi: Ayrılacak Mmap Pointer'ı
5 * sizeof(türü): Serbert bırakılacak bayt sayısı. Genelde tüm Mmap'i kapsıcak şekilde yazılır. Örnekte olduğu gibi...
Şimdi Malloc ve Calloc'da veridiğimiz örneği Mmap ile yapalım. Ancak dikkat! Bu işlemler sadece Unix(Linux ve MacOS) tabanlı işletim sistemlerinde çalışmaktadır. Windows için ayrı bir konumuz olucaktır.
#include <stdio.h>
#include <sys/mman.h> // Mmap bu kütüphanede yer almaktadır

int main(){

	int *bellegimiz = (int *)mmap(NULL, 2 * sizeof(int), PROT_WRITE | PROT_WRITE, MAP_ANON | MAP_PRIVATE, 0 ,0);
	if (bellegimiz == MAP_FAILED)
	{
		printf("Mmap belleği ayrımadı!"); // Linux'da Türkçe karakter destiği mevcuttur
		return 1;
	}

	*bellegimiz = 12;

	printf("Ozel ayrilan bellek alaninda 0. Index'deki deger: %d\n", *(bellegimiz)); // Çıktı 12 olucaktır
    printf("Ozel ayrilan bellek alaninda 1. Index'deki deger: %d\n", *(bellegimiz + 1)); // Çıktı 0 olucaktır. Çünkü Mmap aynı Calloc gibi çalışır

	if (munmap(bellegimiz, 2 * sizeof(int)) != 0) // Eğer serbest bırakılma başarız ise
	{
		printf("Mmap belleği serbest bırakılamdı!");
		return 1;
	}
 
	return 0;
}

Şeklinde yeniden yazılır.

POSIX Shared Memory

Shared Memory, başta da anlattığımız gibi Shared Memory iki uygulamın iletişimi için bellekte açtığımız alanlardır. Mmap, bizlere bu altyapıyı sunar fakat iki uygulama arasında iletişim yani Shared Memory yapabilmemizi sağlamaz. İşte bu durumda POSIX standartı altındaki Shared Memory kütüphanesine başvururuz.
Tabi Shared Memory tek başına yetmez. İlk belleği talep ederiz. Ardından ftruncate adından bir fonksiyon ile biçimlendirme ve bayt cinsinden talep edeceğimiz alan için boyutu ayarlarız. Ardından Mmap aracığılı ile yazdırma işlemlerimizi gerçekleştiriz. Shared Memory yapmamız için şu kütüphaneleri kurmamız gerek;.
#include <fcntl.h>
#include <sys/shm.h>
#include <sys/stat.h>
#include <sys/mman.h>
#include <unistd.h>

Bu kütüphaneler lazım olucaktır.
Bu kütüphaneleri içeren kodlarımız için;

Shared Memory ile açtığmız belleği serbest bırakmak için shm_unlink ile yapılır.
Şimdi Shared Memory ile iki ayrı uygulama olucak şekilde yeniden yazalım. Sistemimiz klasik bir mesaj olan "Hello World" olsun. Birinci uygulamanın ismi "acan.c", kendisi Shared Memory'i açsın ve veriyi yazsan fakat açılan belleği kapatmasın. İkinci uygulamanın ismi ise "kapatan.c" olsun, orda belleği açsın ve veriyi ekrana yazdırsın ve belleği serbest bıraksın.
İlk olarak acan.c kod dosyasını yazalım;
#include <stdio.h>
#include <stdlib.h>
#include <fcntl.h>
#include <sys/shm.h>
#include <sys/stat.h>
#include <sys/mman.h>
#include <unistd.h>

int main(){

    int shm_bolme = shm_open("Isim", O_CREAT | O_RDWR, 0666);
    // "Isim"; Shm isim tabanlı bellek iletişimi sağlar. Açılacak olan Shared Memory'i "Isim" ile açar
    // O_CREAT | O_RDWR; O_CREAT: Yoksa oluştur. O_RDWR: Yazılabilir yap
    // 0666; Açılma modu

    ftruncate(shm_bolme, 20 * sizeof(char)); // Biçimlendirmek
    // shm_bolme; Biçimlendirelecek Shm ögesi
    // 20 * sizeof(char); Özel alan için ne kadar bayt ayrılmalı. Hello World için 20 Char'lık bir alan ayırdık

    char *bellegimiz = (char *)mmap(NULL, 20 * sizeof(char), PROT_WRITE, MAP_SHARED, shm_bolme, 0); // Bağlanma

    sprintf(bellegimiz, "%s", "Hello World"); // Veri yazma işlemi

    return 0;
}

Şimdi ise yeni bir kod dosyası(kapatan.c) oluşturalım ve içeriğini yazalım;
#include <stdio.h>
#include <stdlib.h>
#include <fcntl.h>
#include <sys/shm.h>
#include <sys/stat.h>
#include <sys/mman.h>
#include <unistd.h>

int main(){

    int shm_bolme = shm_open("Isim", O_RDONLY, 0666);

    ftruncate(shm_bolme, 20 * sizeof(char));

    char *bellegimiz = (char *)mmap(NULL, 20 * sizeof(char), PROT_READ, MAP_SHARED, shm_bolme, 0);

    printf("%s", bellegimiz); // İçeriği okuma

    shm_unlink("Isim"); // İşimiz bittiği için belleğimizi serbest bırakıyoruz

    return 0;
}

Windows Shared Memory

Windows'da Shared özelliği Linux'daki kadar kolay değildir. Windows'da ilk önce bir Handle, daha sonra ise Map tanımlamamız gerekir. İki fonksiyonda başarısız olursa ise NULL dönerler. Ayrıca Windows'un kütüphanesi olan #include <Windows.h> kullanılır.

HANDLE

HANDLE hnd = CreateFileMapping
(
    INVALID_HANDLE_VALUE,
    NULL,
    PAGE_READWRITE,
    0,
    10 * sizeof(int),
    "Local\\Hnd"
);

CloseHandle(hnd); // Handle'ı kapatır.

INVALID_HANDLE_VALUE: Dosya sayfalama yapma.
NULL: Varsayılan güvenlik özelliklerini kullan.
PAGE_READWRITE: Okumaya ve yazmaya izin ver.
0: Boyutunun en üsteki DWORD'u.
10 * sizeof(int): İstenilen bayt.
"Local\\Hnd": Paylaşılan belleğin ismi. Tıpkı Linux'da olduğu gibi tanımlanır. Lakin bu "Local\\" şeklinde kullanılır.

Map

int* shrd = (int *)MapViewOfFile    
(
    hnd,
    FILE_MAP_ALL_ACCESS,
    0,
    0,
    10 * sizeof(int)
);

UnmapViewOfFile(shrd); // Map'i serbest bırakır.

hnd; HANDLE'nın ismi.
FILE_MAP_ALL_ACCESS; Okuma ve yazmaya izin ver.
0; Yüksek mertebeden kaydırma.
0; Düşük mertebeden kaydırma.
10 * sizeof(int); İstenilen bayt. Genelde Handle ile aynı olur.
Şimdi ise öğrendiklerimizi bir uygulamay dökelim. Örneğimiz önceki gibi bir "acan.c" diğeri ise "kapatan.c" olucak. "acan.c" Handle ve Map'i açıcak ve Integer olarak bizlere kırk iki ve sekiz sayılarını yazıcak. "kapatan.c" ise o yazılan verileri aynı Shared Memory'den çekicek ekrana toplamları olan elli sonucu yazdırıcak.
İlk olarak acan.c;
#include <stdio.h>
#include <Windows.h>

int main()
{
    HANDLE hnd = CreateFileMapping
    (
        INVALID_HANDLE_VALUE,
        NULL,
        PAGE_READWRITE,
        0,
        10 * sizeof(int),
        "Local\\Hnd"
    );
    if (hnd == NULL)
    {
        perror("HATA!");
        return 1;
    }

    int* shrd = (int *)MapViewOfFile    
    (
        hnd,
        FILE_MAP_ALL_ACCESS,
        0,
        0,
        10 * sizeof(int)
    );
    if (shrd == NULL)
    {
        perror("HATA!");
        return 1;
    }
    
    *shrd = 4;
    *(shrd + 1) = 34;

    getchar(); // Programı bekletiyoruz. Çünkü Windows'da bir Shared Memory ile işlem yapan son işlemde kapanırsa otomatik Windows bizim açtığımız Shared Memory'ide kapatıyor. Biz 2 dosyalı bir sistem kuracağımız için program beklemeli

    return 0;
}
