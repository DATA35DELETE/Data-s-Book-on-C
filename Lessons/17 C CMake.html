CMake

CMake Nedir?

CMake; C, C++ vb. dillerin için geliştirmiş ve açık kaynak olan bir derleme otomasyon aracıdır.
CMake büyük ve kapsamlı projelerde kod ve derleme yönetimi için kritik önem arz etmektedir. Bu sayfadan önce sürekli gcc ile derleme ve kütüphane bağlama yaptık. Bu şuan kolay olsada ileride bir proje için yüzlerce kütüphane içericek olursa o gcc komutu yazmak çok ama çok uğraştırıcı olucaktır. İşte bu durumda CMake devreye girer. CMake bizlere "CMakeLists.txt" adında bir derleme talimatlarını içeren bir dosya formatı sağlar. Biz bu talimatları CMake'e özgü bir yazılış stili ile yazarız. Bir kere yazarız ve tek ve basit bir komut ile her seferinde gcc'de olduğu gibi yazmamız gerekmez. Böylelikle zamandan tasaruf etmiş oluruz.
Aslında CMake, Makefiles adında bir otomasyon aracının üstüne kurulu bir sistemdir. Hatta Build klasöründe Makefile dosyasını görebilirsiniz.
Bu eğitimde serisi boyunca kullandığımız Visual Studio Code'u kullanmayı devam ediceğim.
CMake derlenen uygulamalardan tam olarak sorumlu değildir. CMake'de arka planda derleme işini yapan yapılar ise "Generators" olarak adlandırılan derliyicilerdir. CMake ise bu derliyicileri doğru şekilde yönetip derleme yapması onu derleme otomasyonu olmasını sağlar.

CMake Kurulumu

CMake'i kurmak için tabiki de Mingw'i kullanıcağız. Çünkü Gcc ve diğer derliyiciler Mingw'de bulunmaktadır. Tabi sisteminizde Visual Studio C++ SDK'i kurulu ise onun içerisindeki derliyicileride kullanabilirsiniz. Ben Gcc kullanmayı tercih ettim.
Mingw konsolunda bu komutu çalıştıralım:
pacman -Sy mingw-w64-x86_64-cmake

Güncelleme ve kurulumun ardından cmake sistemize kurulmuş demektir.
Artık CMake'i kullanabiliriz.

Build ve Source Klasörleri

CMake ile proje geliştirmeden önce bu iki klasörü anlamamız gerek.
Build klasörü, Source klasöründeki kodların derlenmiş ve çalıştırabilir olan dosyaları içerir. Source ise derlenecek kaynak kodların ve CMakeLists.txt talimat dosyasının bulunduğu klasördür. CMake'in görevi ise bu kısımda Source klasöründeki kaynak kodlarını alıp Build klasörüne derlemektir.
Bu iki klasörün kullanım şekilleri ile ilgili temelde iki durum ortaya çıkmıştır. Source içi Build ve Source dışı Build. Aynı göreve hizmet eden iki durumdan birisi olan Source içi Build için yapılan işlem Build klasörünün Source içinde olmasıdır. Source dışı Build ise bir ana dizin içerisinde hem Source hem de Build farklı klasörlerde olma durumudur. Bu ve diğer sayfalarda Source dışı Build kullanmakta olacağım.

CMakeLists.txt Talimat Kodları ve CMake ile İlk Derleme

İlk olarak şu klasör yapısını kuralım.
projeDizini
├───build
└───source
        CMakeLists.txt
        main.c
CMakeLists.txt içerini yazalım
cmake_minimum_required(VERSION 4.3.2) # CMake'in sürümünü belirleyelim

# CMakeLists.txt'de diyez(#) işaret ile yorum satırı yazılabilir
 
project(datasbookonc) # Genel projemizin ismi

add_executable(hello) # Çalıştırabilir bir dosya tanımlama. İsmi "hello" olsun
target_sources(hello PRIVATE main.c) # CMakeLists.txt'de bir nevi değişken mantığı vardır. "hello" isimli çalıştırabilir olan dosyamızn kaynak dosyasını main.c olarak belirledik
        
Ardından basit bir örnek için main.c kaynak dosyasını buları yazalım.
#include <stdio.h>

int main()
{
    printf("Hello World");

    return 0;
}
Sonra build klasörüne gelip şu komutu çalıştıralım
cmake -G "MinGW Makefiles" ..\source
-G "MimGW Makefiles"; Hangi ortam için Makefiles kullanılacak
..\source; Source klasörünüz

Son olarak derleme için ise bu komutu çalıştırıyoruz
cmake --build .

hello

Çıktı "Hello World" olucaktır.

Çoklu Dosya Derleme

Çoklu dosya derlemek için CMakeLists.txt "hello" adlı çalıştıralabilir dosyaya kaynak dosyası eklememiz gerekir.
Ondan önce diğer dosyaları oluşturalım. Başlık dosyalarındaki örneğimizi CMake ile tekrar yapalım.

main.c
#include <stdio.h>
#include "topla.h"

int main(){

    printf("2 + 2 = %d", topla(2, 2));

    return 0;
}

topla.h
#ifndef _TOPLA_H
#define _TOPLA_H

int topla(int a, int b);

#endif

topla.c
int topla(int a, int b)
{
    return a + b;
}

CMakeLists.txt
cmake_minimum_required(VERSION 4.3.2)
 
project(datasbookonc)

add_executable(topla)
target_sources(topla PRIVATE main.c topla.h topla.c)
# Diğer kaynak dosyalarımızı ekledik

Build edelim ve çıktısı "2 + 2 = 4" olucaktır.

Kütüphane Oluşturma

CMake'de kütüphane oluşturmak için az önceki örneğimizi hem statik hem de dinamik kütüphane şeklinde CMake ile derliyelim.
cmake_minimum_required(VERSION 4.3.2)
 
project(datasbookonc)

include_directories(.) # Kütüphanenin başlık dosyalarının bulunduğu klasör.
add_library(topla STATIC/SHARED topla.c)
# STATIC; Statik kütüphane oluşturur
# SHARED; Dinamik kütüphane oluşturur

Dış Kütüphane Bağlama

Eğer statik veya dinamik bir kütüphane bağlamak istersek;
cmake_minimum_required(VERSION 4.3.2)
 
project(datasbookonc)

LINK_DIRECTORIES(${PROJECT_SOURCE_DIR})
# Kütüphane dosyalarıı kaynak dizininde ara

add_executable(main)
target_link_libraries(main PRIVATE libtopla.dll)
# Kaynak dizininde bulunan kütüphanemizi main uygulamsına linkle

target_sources(main PRIVATE main.c)


Zlib gibi bir kütüphane bağlamak istersek;
cmake_minimum_required(VERSION 4.3.2)
 
project(datasbookonc)

find_package(ZLIB REQUIRED)
# Zlib kütüphanesini bul

add_executable(main main.c)
target_link_libraries(main PRIVATE ZLIB::ZLIB)
# Zlib kütüphanesini linkle
